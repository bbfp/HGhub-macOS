# HGhub macOS 自用版需求

状态：需求已由用户于 2026-11-04 确认。S0 候选已实现并生成 App/DMG；本地自动检查与 macOS 合成视频播放已验证，真实源站仍未验证。交付状态以 VALIDATION.md 为准。

## 目标与范围

- 仅面向用户自己的 Apple Silicon Mac；不要求 Intel Mac、其他平台适配或公开发布。
- 在现有 HGhub 基础上保留全部在线功能：推荐、分类、搜索、排行榜、短剧/帖子浏览与播放、登录注册、评论、点赞、收藏、关注及本地记录。
- 交付可双击运行的 Apple Silicon `.app` 和便于安装的 `.dmg`。接受未签名，提供首次启动说明；本轮不做 Apple 签名、公证、App Store 发布、自动更新或多人使用支持。
- 实用优先，分 S0/S1/S2 交付；覆盖正常使用及必要失败处理，不以极端测试和完美打磨拖延可用版本。

## 下载与本地使用

- 在线浏览/播放和主动下载并存；逐集选择为基础，提供整剧全选及多短剧加入任务的入口。
- 下载视频、封面及必要元数据；每集优先保存为 `.mp4`，必要的媒体合并/转换组件随 App 打包，避免使用时再安装开发工具。
- 提供 App 内“本地下载”入口，断网可浏览已下载内容并播放。
- 可设置默认下载根目录，每部短剧自动建立独立文件夹；单次下载可覆盖目标目录。
- 支持多个任务同时执行，自动限制并行数，并在多个短剧之间合理分配下载机会；具体并行数和方式在调研后确定。
- S0 即提供可操作的暂停、取消、失败重试，以及任务进度；退出后保存任务，下次启动继续未完成下载。
- 下载并发在“我的 → 本地下载”中手动配置并持久化：全局同时下载任务默认 5，同一部剧同时下载集数默认 3，每集同时下载分片默认 4。一个任务对应一集，同剧集数计入全局任务数，默认满载最多 20 个分片。运行中降低上限时已有操作自然完成，再按新值补充。旧版 v1 设置缺少新增字段时使用上述默认值。
- 当前旧 App 正在下载时，开发与验证使用独立目录，不重启、覆盖旧 App，也不写入其任务或设置文件；新构建独立暂存，下载结束后再切换。
- 封面等图片下载后持久化缓存，避免以后打开时反复下载；快速打开是目标，尚无性能实测。

## 兼容与迭代

- 从 S0 起明确下载目录结构、文件命名及带版本号的元数据格式。
- S1/S2 必须继续读取、管理和使用旧版已下载内容；必要的元数据升级保持旧内容可用。
- S0 包含可运行 App、上述在线功能、目录选择、单集/整剧下载、有限并行、暂停/取消/重试、退出恢复及离线播放。S1/S2 的优化由调研及总计划排序。
- 不重做 Windows/Android 平台；新增 macOS 目标时尽量保持现有行为。

## 已确认工作流

1. 先理解仓库并完成需求对齐（已确认）。
2. 使用 Claude Code，精确请求 Opus 5.5，使用 medium/high/xhigh 中适当的 effort；由 Claude 先出第一版调研方案，再讨论迭代。
3. 以 GitHub 为主，兼顾 GitLab、Hugging Face 等 Git 平台，调查本项目的 macOS 改造、Windows/Android 在 Mac 上的运行路径、Mac 原生同类客户端及可复用下载/缓存组件；按相关性、可行性、实用性和质量筛选。
4. 执行调研，保留可追溯证据和限制。
5. 将完整需求与调研结果带回同一个 Claude Code session，由 Claude 生成总任务计划，讨论后按 S0/S1/S2 实施和验证。

## 验证边界

静态阅读、构建通过、合成用例和真实在线/离线使用分别记录。不得将编译成功或模拟测试视为用户电脑上的真实播放、续传和跨版本兼容已验收。源站可达性、播放链接有效期及内容可用性需要实际检查。
