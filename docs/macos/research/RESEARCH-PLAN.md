## 四、筛选表字段与路线淘汰规则

### 4.1 通用字段（所有候选）

- 名称、URL、检索式、访问日期
- 许可证（取自 LICENSE 文件，写出 SPDX 标识）、与分发方式的兼容性
- 最近 commit 与 release 日期、是否 archived、近 12 个月 issue 处理情况（仅记录，不作硬条件）
- 语言与平台、是否有 arm64 产物或能在 arm64 运行
- 依赖数量、漏洞扫描结果（`cargo audit` / `npm audit` / osv-scanner，记录版本）
- 是否捆绑未声明的二进制
- 功能证据（每项附代码位置）：AES-128、EXT-X-MAP、Range、断点、并发、key rotation
- 集成成本：改动范围、体积增量、需要的额外依赖
- 本地复现结果：探针编号、命令、结果、日志路径
- 结论（采用 / 借鉴设计 / 淘汰）、理由、置信度（高 / 中 / 低）

### 4.2 各路线专属字段与淘汰规则

**Route A：直接适配 Tauri 为原生 macOS**
- 专属字段：是否能生成 `.app` 与 `.dmg`、`hg` 协议在 macOS 的 URL 形式（官方文档与 P-4 实测）、WKWebView 播放路径（M-2 或替代）。
- 淘汰：P-4 构建失败且修复超出本次时间盒；或 `hg` 协议 / MSE 路径在 macOS 上无法通过替代检查且无已知修复；或为适配所需的平台分支复杂度明显超过重写 UI 的成本（需在 G4 说明依据）。

**Route B：VM / 兼容层 / Android 运行**
- 专属字段：是否支持 Apple Silicon、许可条款是否允许该用途、产物是否为 `.app`（通常不是，应明确标注）、文件路径与网络行为差异。
- 淘汰：作为最终交付物一律淘汰；仅在 Route A 被淘汰后保留为"快速自用对照"。许可条款不明确或禁止该用途，则不推荐。

**Route C：Mac 或跨平台同类应用**
- 专属字段：可借鉴的交互点（本地库、下载队列、封面缓存、离线播放）、代码许可、技术栈。
- 淘汰：无可复用设计点；许可证不兼容且只能参考但无法借鉴；技术栈迁移成本远超本方案范围。Swift/Electron 项目仅作设计参考，不推荐整体替换。

**组件轨道（HLS / FFmpeg / 队列）**
- 专属字段：见 4.1，并增加 FFmpeg 构建配置行与许可证结论。
- 淘汰：无法处理 AES-128；FFmpeg 构建的许可证义务无法在自用分发方式下满足且无替代；队列实现无法满足"全局上限 + 每任务上限"要求。

### 4.3 FFmpeg 分发边界（不以仓库 MIT 代替）

- 记录所用 FFmpeg 的 `ffmpeg -version` 与 `configuration:` 行。
- 判断是否含 `--enable-gpl` 或 GPL/非自由组件。
- 记录 LGPL 构建下的动态或静态链接方式、是否随 `.app` 分发、源码获取方式。
- 自用不对外分发时义务较轻，但仍需保留许可证文件与构建配置记录。若 `.dmg` 交给他人，即视为分发，需重新判断。

## 五、续传身份校验（不变，作为门禁）

复用已下载分片前必须逐段核对：
- 集数标识与 playlist 来源
- 序号（`EXT-X-MEDIA-SEQUENCE` 加索引）
- 相对路径或 URI 哈希
- `EXTINF` 时长
- 本地文件大小与保存的 SHA-256
- key URI 哈希与 key 内容哈希（key 本身不写入产物）
- IV（显式值，或序号推导规则）
- `EXT-X-MAP` 身份（如有）

任一不一致则重新下载该段。合并后用 `ffprobe` 时长与 `EXTINF` 之和比较，允许合理误差。

**不能仅凭分片数量或大小一致判定可复用。**
